# Canonical mods: in-game checklist

The canonical mods ([#138](https://github.com/kjmikkel/PillarsDialogEditor/issues/138)) are generated by the editor and
checked by automated tests: through every install route, as files on disk, and for PoE1 through the game's own loader.
What those tests can't tell is how the **running game** treats the result. This checklist covers that part. Run it
once per game, record the result at the bottom, and file what fails as an issue.

Each row below is one feature of a mod. The tag in backticks matches a row of that mod's README
([PoE1](../DialogEditor.Tests/Fixtures/CanonicalMod/poe1/README.md),
[Deadfire](../DialogEditor.Tests/Fixtures/CanonicalMod/poe2/README.md)), and a test fails if a feature has no row here.
Where a feature exposes an open issue, the row names it and says what the issue predicts. Record that behaviour; it is
not a new failure.

The console commands come from the games' decompiled code. Anything that code could not settle is marked
**confirm on the first run**. When a command or an expectation turns out wrong, correct this file in the same commit as
the results.

## Before you start (both games)

- **Use a throwaway save.** Turning cheats on disables achievements for that save. Back up your save folder first.
- **Note the game build** (shown on the main menu) for the results table.
- **Find the game's log.** Unity writes it under `%USERPROFILE%\AppData\LocalLow\`, in the publisher's folder for the
  game (`output_log.txt` or `Player.log`; confirm on the first run). You check it after each game.
- **Build `dialog-patcher`** (the `DialogEditor.PatchCli` project), or take it from a release.
- **Open the console.** Use the console key, which is backquote/tilde on most layouts (confirm on the first run). Type
  `iroll20s` to turn cheats on: both games run script functions such as `StartConversation` and `SetGlobalValue` from the
  console only then. `PrintGlobal <name>` shows a global's value.
- **The NPC speaker is invented** and isn't in the world, so the conversation has no one to face. Record how the game
  presents that (portrait, name, camera).

Copy the setup files with `robocopy <source> <game folder> /E /XC /XN /XO`, which adds files and never replaces one.
None of the files exist in a real install.

## Pillars of Eternity

**Setup**

1. Copy `DialogEditor.Tests/Fixtures/Canonical/poe1` into the game folder (the folder that contains
   `PillarsOfEternity_Data`). This adds the `canonical` conversation and its `en` and `de` stringtables.
2. Run `dialog-patcher "<game folder>" DialogEditor.Tests/Fixtures/CanonicalMod/poe1/canonical_mod.dialogpack`.
3. Start the game, load the throwaway save, open the console and type `iroll20s`.
4. PoE1 reads a global that was never set as **-1**, not 0, which would change how the conditions below come out.
   Set each one the rows use to 0 first: `SetGlobalValue <name> 0` for `cm_flag_a`, `cm_flag_b`, `cm_flag_c`,
   `cm_flag_node`, `canonical_flag_d`, `canonical_seen` and `cm_extra`.

**Start the edited conversation** with
`StartConversationFacingListener oei_player Assets/Data/Conversations/Canonical/canonical.conversation 0`. Use the
full path: PoE1 matches the typed name against *any part* of a conversation's file name, so `canonical` alone also matches
`canonical_mod_new` and is refused as ambiguous. Start it again whenever a row asks for a fresh run.

**Rows, in play order**

- [ ] `text.edit-with-female`: the first line reads "Welcome back, [Player Name]. The mod changed this line." with your character's name. A female main character sees "…, too." at the end.
- [ ] `scripts.remove`: after the first line, `PrintGlobal canonical_seen` is still 0, the value setup gave it (the mod removed node 0's script that set it to 1).
- [ ] `nodes.add-player-choice`: with all flags at 0 there are three choices. The new fourth choice is hidden (see the next row).
- [ ] `conditions.node-nested`: `SetGlobalValue cm_flag_a 1` and `SetGlobalValue cm_flag_b 3`, then start a fresh run. The fourth choice appears. `SetGlobalValue cm_flag_b 0` (with `cm_flag_c` still 0) hides it again; set it back to 3 for the next rows.
- [ ] `text.markup`: the fourth choice's text is "Ask about the <i>canonical</i> mod.". PoE1's text renderer probably doesn't understand `<i>`, so record whether *canonical* shows in italics or the tags show literally.
- [ ] `nodes.add-script`: pick the fourth choice. The conversation passes through a script node and ends.
- [ ] `scripts.add-all-categories`: after picking the fourth choice, `PrintGlobal cm_enter` is 1 and `cm_exit` is 2. `cm_update` is 3 if the game ran the node's update script; record which.
- [ ] `conditions.replace-nested`: `SetGlobalValue cm_flag_node 1` hides the first choice ("Take the scripted path."). `SetGlobalValue cm_flag_node 0` brings it back.
- [ ] `conditions.clear`: `SetGlobalValue canonical_flag_d 9`. The second choice ("Draw from the bank.") is still offered; before the mod it needed `canonical_flag_d` below 5.
- [ ] `links.remove`: pick the second choice. The conversation ends there (the mod cut its link to the bank).
- [ ] `scripts.add-to-existing`: pick the first choice. Afterwards `PrintGlobal cm_extra` is 1, and `canonical_stage` is 3 (the existing scripts still ran).
- [ ] `props.speaker-listener`: after the narrator's line, the closing line "That is everything. Farewell." is spoken by the narrator, not the NPC.
- [ ] `nodes.add-npc-line`: the new line after it ("A new closing line, written by the canonical mod.") is **not** shown, because the mod also set it to Hidden (next row). The conversation ends cleanly.
- [ ] `props.display-and-persistence`: the new closing line is Hidden, and the fourth choice is a Bark and can be picked once per conversation. Record anything odd. The other values are on nodes play doesn't reach and are checked by the automated tests.
- [ ] `vo.filename`: no voice plays for the hidden line (its `VOFilename` names a file that doesn't exist). Note any log line about it.
- [ ] `nodes.convert-player-to-npc`: the first line offers only two choices; the third ("Hand over to another conversation.") is gone. It is an NPC line now, and the game moves on to an NPC line only when no player choice is on offer (`GetNextNode` skips talk nodes while there are choices; confirm on the first run). To see it, start at that node: `StartConversationFacingListener oei_player Assets/Data/Conversations/Canonical/canonical.conversation 3`. The NPC speaks "Hand over to another conversation." to the player.
- [ ] `kept.bank-and-trigger`: continue from the line above (started at node 3). The trigger hands over to `canonical` and the first line plays again. The comments the mod added aren't visible in play; the automated tests check them.
- [ ] `nodes.delete`: not reachable in play, because the bank is cut off (`links.remove`). The automated tests check that the bank no longer lists the deleted node.
- [ ] `links.weight`: not visible in play (weights only matter between NPC lines picked at random); checked by the automated tests.
- [ ] `links.display-values`: not visible in play, because no choice here is a question node. The new link's ShowAlways is checked against the game's own model by the automated tests. Note anything the log says about the conversation's links.
- [ ] `props.comments-and-direction`: not visible in play; comments and actor directions are author notes. Checked by the automated tests.
- [ ] `text.second-language`: switch the game to German, if your build offers it. The first line reads "Willkommen zurück, [Player Name]. Der Mod hat diese Zeile geändert."
- [ ] `conversation.new`: `StartConversationFacingListener oei_player canonical_mod_new 0`. The NPC says "Hello from a conversation the mod created.", then two choices. "Second choice, only when cm_flag_a is set." shows only with `cm_flag_a` at 1. Both choices lead to "Goodbye."

**After the run:** read the log for errors that mention `canonical`.

## Deadfire

**Setup**

1. Copy `DialogEditor.Tests/Fixtures/Canonical/poe2` into the game folder (the folder that contains
   `PillarsOfEternityII_Data`). This adds the `canonical` bundle, its `en` and `de` stringtables, and node 7's two
   placeholder voice files.
2. Copy `DialogEditor.Tests/Fixtures/CanonicalMod/poe2-ingame` into the game folder too. It adds:
   - `canonical_conversations.manifest`: Deadfire finds conversations only through a manifest;
   - `canonical.globalvariablesbundle`: Deadfire refuses to set a global it hasn't declared.
3. Run `dialog-patcher "<game folder>" DialogEditor.Tests/Fixtures/CanonicalMod/poe2/canonical_mod.dialogpack`.
4. Start the game (the manifest and globals load at start-up), load the throwaway save, open the console and type
   `iroll20s`.

**Start the edited conversation** with `StartConversation oei_player canonical 0`. Deadfire matches the exact file
name. Start it again whenever a row asks for a fresh run.

**Rows, in play order**

- [ ] `text.edit-with-female`: the first line reads "Welcome back, [Player Name]. The mod changed this line." with your character's name. A female main character sees "…, too." at the end.
- [ ] `scripts.remove`: after the first line, `PrintGlobal canonical_seen` is still 0 (the mod removed node 0's script that set it).
- [ ] `nodes.add-player-choice`: with all flags at 0 there are three choices. The new fourth choice is hidden (see the next row).
- [ ] `conditions.node-nested`: `SetGlobalValue cm_flag_a 1` and `SetGlobalValue cm_flag_b 3`, then start a fresh run. The fourth choice appears. `SetGlobalValue cm_flag_b 0` (with `cm_flag_c` still 0) hides it again; set it back to 3 for the next rows. The editor writes new calls without a function hash; Deadfire ignores stored hashes when it loads a call, so they are expected to work.
- [ ] `text.markup`: the fourth choice reads "Ask about the *canonical* mod.", with *canonical* in italics.
- [ ] `nodes.add-script`: pick the fourth choice. The conversation passes through a script node and ends.
- [ ] `scripts.add-all-categories`: after picking the fourth choice, `PrintGlobal cm_enter` is 1 and `cm_exit` is 2 (node 13 ends the conversation, so its OnExit runs). `cm_update` stays 0: Deadfire never runs a script node's update scripts.
- [ ] `conditions.link`: `SetGlobalValue cm_flag_link 1`, then pick the first choice ("Take the scripted path."). The conversation ends, because the mod's negated condition on that link fails. The choice is now marked read (it is OnceEver): run `ClearConversationNodeAsRead canonical 1` before every later pick of it. With `cm_flag_link` at 0 it continues to the script node and the narrator.
- [ ] `scripts.keep-per-script-conditional`: with `cm_flag_link` at 0, `SetGlobalValue canonical_stage 0`, clear node 1 as above and take the first choice: `PrintGlobal canonical_stage` reads 1. Then `SetGlobalValue canonical_stage 7`, clear node 1 and take it again: it still reads 7, because node 4's OnEnter script runs only while the stage is 0 (#115). Reading 1 means the conditional was lost. `cm_extra` stays 0 and the stage gets no +2: Deadfire skips a script node's exit scripts when the node leads on.
- [ ] `conditions.clear`: `SetGlobalValue canonical_flag_d 9`. The second choice ("Draw from the bank.") is still offered; before the mod it needed `canonical_flag_d` below 5.
- [ ] `links.remove`: pick the second choice. The conversation ends there (the mod cut its link to the bank).
- [ ] `vo.off`: the narrator's line after the script node plays no voice (the mod turned its VO off).
- [ ] `props.speaker-listener`: the closing line "That is everything. Farewell." is spoken by the narrator, not the NPC.
- [ ] `props.hide-speaker`: the closing line now shows its speaker (the mod turned HideSpeaker off).
- [ ] `vo.alias`: the closing line may try to play node 7's voice file through its alias (confirm on the first run whether Deadfire uses an alias on a line without HasVO). The files are 4 placeholder bytes, so expect silence; record any log line naming `narrator/canonical_0007`.
- [ ] `nodes.add-npc-line`: the new line after it ("A new closing line, written by the canonical mod.") is **not** shown, because the mod also set it to Hidden (next row). The conversation ends cleanly.
- [ ] `props.display-and-persistence`: the new closing line is Hidden, and the fourth choice is a Bark and can be picked once per conversation. Record anything odd. The other values are on nodes play doesn't reach and are checked by the automated tests.
- [ ] `vo.import`: the hidden line has imported voice (`narrator/canonical_0011.wem`, placeholder bytes). Expect silence; record any log line about it.
- [ ] `nodes.convert-player-to-npc`: the first line offers only two choices; the third ("Hand over to another conversation.") is gone. It is an NPC line now, and the game moves on to an NPC line only when no player choice is on offer (`GetNextNode` skips talk nodes while there are choices; confirm on the first run). To see it, start at that node: `StartConversation oei_player canonical 3`. The NPC speaks "Hand over to another conversation." to the player.
- [ ] `kept.bank-and-trigger`: continue from the line above (started at node 3). The trigger hands over to `canonical` and the first line plays again; with the mod's new Persistence, record whether a second hand-over in the same run behaves differently.
- [ ] `nodes.delete`: not reachable in play, because the bank is cut off (`links.remove`). The automated tests check that the bank no longer lists the deleted node.
- [ ] `links.weight`: not visible in play (weights only matter between NPC lines picked at random); checked by the automated tests.
- [ ] `links.display-values`: not visible in play, because no choice here is a question node; checked by the automated tests.
- [ ] `text.second-language`: switch the game to German, if your build offers it. The first line reads "Willkommen zurück, [Player Name]. Der Mod hat diese Zeile geändert."
- [ ] `conversation.new`: `StartConversation oei_player canonical_mod_new 0`. Deadfire finds it through the manifest the patcher wrote (`design/manifests/dialogeditor_canonical_mod_new.conversations.manifest`). The NPC says "Hello from a conversation the mod created.", then two choices. "Second choice, only when cm_flag_a is set." shows only with `cm_flag_a` at 1. Both choices lead to "Goodbye."

**After the run:** read the log for errors that mention `canonical`, and for warnings about undeclared globals.

## What to record

- How each game presents a conversation whose speaker isn't in the world.
- Every row that didn't match: the row, what you saw, and any log line.
- Whether Deadfire runs the condition and script calls the editor wrote without a function hash
  (`conditions.node-nested`, `scripts.add-all-categories`). The decompiled loader says it ignores stored hashes;
  this run confirms it.

## Clean up

1. `dialog-patcher "<game folder>" --restore`. This undoes every patcher change, including the files it created for
   `canonical_mod_new` and the imported voice file.
2. Delete the setup files you copied:
   - **Pillars of Eternity**, under `PillarsOfEternity_Data/data`:
     - `conversations/canonical/` (the folder);
     - `localized/en/text/conversations/canonical/` and `localized/de/text/conversations/canonical/` (the folders).
   - **Deadfire**, under `PillarsOfEternityII_Data`:
     - `exported/design/conversations/canonical.conversationbundle`;
     - `exported/localized/en/text/conversations/canonical.stringtable` and the same file under `de`;
     - `StreamingAssets/Audio/Windows/Voices/English(US)/narrator/canonical_0007.wem` and `canonical_0007_fem.wem`;
     - `exported/design/manifests/canonical_conversations.manifest`;
     - `exported/design/globalvariables/canonical.globalvariablesbundle`.
3. Verify the game files in your launcher (GOG Galaxy or Steam).
4. Restore your save folder, or delete the throwaway save.
